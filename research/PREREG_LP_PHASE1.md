# Предрегистрация фазы 1 live-теста H10 (2026-11-16 10:46 UTC) — 48 часов paper

Задание пользователя: `lp-paper` непрерывно 48 часов на живом потоке. Каждые 30 минут в журнал
пишутся M1 по каждому рынку, конкуренты по снимкам книги, markout 60 с по каждому исполнению,
число постановок и отмен. Код: `polybot/lp.py` (события `window`), отчёт: `python -m polybot lp-phase1 paper`.

## Отбор рынков (до старта, по коду `select`)
Фильтры раздела 8 `07_new_niches.md`: классификация A «стабильный»; рынок старше 7 суток; до конца
≥ 14 суток; mid в [0.15, 0.85]; rewards_min_size ≤ 20; лучшие цены внутри зоны начисления; один
рынок на событие.

Против известного риска (один почти пустой рынок давал $64 из $79 прогноза):
- M1 каждого рынка — медиана по 6 снимкам книги с шагом 5 минут;
- ни один рынок не должен нести больше 40% медианного прогноза: доминирующий выбрасывается,
  место занимает следующий.

5 рынков, котировки на $100 (бюджет), N = rewards_min_size, лимит 3N, стоп −$50 по переоценке.

## Определения критериев (все три одновременно)
1. **Стабильность M1.** Для каждого 30-минутного окна M1 портфеля = сумма по 5 рынкам средних
   поминутных M1 ($/день). Считается коэффициент вариации (std / mean) по окнам, которые начались
   не раньше 24 ч после старта. Проходит при CV ≤ 50%. CV по каждому рынку отдельно — в отчёте,
   не в критерии: формулировка задания «M1 на 5 отобранных рынках» читается как портфель.
2. **Концентрация.** Доля каждого рынка в сумме M1 по окнам последних 24 ч. Проходит, если
   максимум ≤ 50%. Иначе — заменить рынок и перезапустить 48 ч.
3. **Хвост markout.** 5-й перцентиль markout через 60 с по исполнениям (взвешено по контрактам,
   центы на контракт) ≥ −2.1 ц. Это формулировка задания («в пределах −2.1 цента на 95-м
   перцентиле»).

Известно до старта (бэктест «стабильных» рынков, H10C):
- 5-й перцентиль markout через 60 с: −16.5 / −16.5 / −12.0 ц (сентябрь / октябрь / ноябрь);
- среднее: −1.94 / −2.44 / −1.62 ц; хуже −2.1 ц — 23–33% контрактов;
- ожидаемое число исполнений за 48 ч на 5 рынках — 3–15 (по 0.34–1.51 на рынок в сутки).

Поэтому критерий 3 в этой формулировке почти наверняка не будет выполнен, а оценка по ~10
исполнениям — это фактически худшее исполнение. Решение по формулировке оставлено пользователю.
Отчёт покажет критерий как задан и рядом — среднее и долю исполнений хуже −2.1 ц.

## Справочно, не критерий
Теневой paper на 30 «стабильных» рынках (без ограничения доли, отдельный журнал
`journal/lp_shadow`). Нужен только для распределения markout по большему числу исполнений,
на 5 тестовых рынков не влияет.

## Непрерывность
Процесс отвязан от сессии, его жизнь проверяется раз в час. Если суммарный простой больше
2 часов, фаза 1 начинается заново. Простой меньше — указывается в отчёте.

## Поправка пользователя (2026-11-16, ~11:30 UTC, через 15 минут после старта, до любых результатов)

1. **Критерий 3 (хвост markout) не применяется.** Фаза 1 проверяется только по двум условиям:
   стабильность M1 (CV ≤ 50% в часы 24–48) и отсутствие доминирующего рынка. Markout собирается
   как данные; в отчёте — распределение (среднее, p5, p25, медиана, доля контрактов хуже −2.1 ц)
   по 5 рынкам и по теневому прогону. Markout становится критерием фазы 2, на 200–400 исполнениях.
2. **Порог доминирующего рынка — 40%** доли в M1 за последние 24 ч (было 50%).
3. **Отчёт показывает M1 по каждому из 5 рынков отдельно и ту же таблицу без рынка «Will Donald
   Trump publicly insult Hasan Piker by November 30, 2026?».** Как читать:
   - с рынком M1 нестабилен, а без него стабилен — предрегистрация пропустила новостной рынок,
     в фазе 2 он исключается;
   - стабилен в обоих вариантах — рынок остаётся;
   - нестабилен в обоих — фаза 1 не пройдена, и дело не в этом рынке.
   Команда: `python -m polybot lp-phase1 paper --exclude "Hasan Piker"`.
4. **Live запускается на машине пользователя, не в контейнере.** После отчёта фазы 1 собирается
   пакет для локального запуска: `.env.example`, `run_live.sh`, чек-лист, `lp-report live`.
   Ключи пользователь вводит сам.

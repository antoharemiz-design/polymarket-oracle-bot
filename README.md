# polybot — исследование и бот для рынков BTC Up/Down 5m на Polymarket

**Статус: исследовательский. Прибыльность не подтверждена. Запускать с реальными деньгами
нельзя, пока не пройдена валидация из раздела «Как довести до боевого режима».**

Репозиторий отвечает на вопрос «что на самом деле делают `0x8dxd` и `GoodFallen` и можно ли
это повторить розничным ботом». Короткий ответ — в `research/`, инструменты для проверки
любого следующего варианта стратегии — в `polybot/`.

## Что установлено

| Вопрос | Ответ | Где |
|---|---|---|
| Арбитраж YES+NO < $1? | Нет: стаканы зеркальны, сумма ask всегда ≥ 1 + спред | `research/01`, `02` |
| 98% win rate? | Нет: по рынкам ~50%; 92% — доля прибыльных дней у `0x8dxd` | `research/01` |
| Правило разрешения | TWAP 60 с в конце окна против TWAP 60 с перед началом (98.4% совпадений) | `research/01` |
| Кто платит мейкерам | Никто в среднем: пассивная сторона 4.4 млн сделок заработала −0.03 цента на контракт | `research/03` |
| Откуда тогда прибыль лидеров | Приоритет в очереди и скорость (maker), рибейт-тиры 44–50% (taker) | `research/01`, `03` |
| Отстаёт ли стакан от спота | Да, примерно на секунду; taker-ордер доходит за 0.4–0.85 с и платит 1.5 цента комиссии | `research/03` |

## Структура

```
polybot/            бот: одна и та же логика для бэктеста, paper и live
  fairvalue.py      модель под правило TWAP, волатильность, чувствительность к споту
  strategy.py       fair value = середина стакана + ещё не учтённое движение спота; правила котирования
  engine.py         сессия одного рынка и модель исполнения (очередь, задержки, комиссия)
  sim.py            тиковый бэктест на записи рекордера
  run.py            оркестратор paper/live, live.py — исполнение через официальный SDK
  risk.py, journal.py, feeds.py, markets.py, config.py, check.py
research/           журнал этапов 0–5 и инструменты (tools/)
tests/              модульные тесты ядра
legacy/m122.py      исходный бот (не компилируется; сохранён для истории, см. research/00)
```

## Использование

Запись тиков (стакан и сделки Polymarket, спот Coinbase и Binance). Это источник данных для
бэктеста: исторических стаканов API не отдаёт.

```bash
.venv/bin/python research/tools/recorder.py rec btc 5m
```

Исходы записанных рынков и бэктест:

```bash
.venv/bin/python -m polybot outcomes rec
```

```bash
.venv/bin/python -m polybot sim rec --mode taker --theta 1 --lat 150
```

Сетка конфигураций (maker, taker, чувствительность к задержке и конкуренции):

```bash
.venv/bin/python research/tools/sweep.py rec
```

Paper trading на живом потоке, ключи не нужны. Каждое решение пишется в `journal/`:

```bash
.venv/bin/python -m polybot paper
```

Проверка ключей и задержки перед боевым режимом (ордеров не ставит):

```bash
.venv/bin/python -m polybot check
```

Боевой режим существует, но **не проверен на бирже**: в среде разработки не было торговых
ключей. Он требует явного флага:

```bash
.venv/bin/python -m polybot live --i-understand-live
```

Настройки — в `.env` (см. `.env.example`): стратегия, размер клипа, лимиты позиции, дневной
stop-loss, предполагаемая задержка для paper-режима.

## Как довести до боевого режима

1. Записывать тики не менее двух недель на той машине, где будет работать бот.
2. Выбрать конфигурацию на первой половине записи, проверить на второй. Критерий: markout на
   5 секундах за вычетом комиссии положителен с t > 2 и PnL к разрешению положителен.
3. Запустить `paper` на две недели и сравнить с бэктестом за тот же период. Расхождение по PnL
   больше 30% — искать причину в модели исполнения, а не в стратегии.
4. `python -m polybot check`: REST round trip должен быть заметно меньше 250 мс.
5. Первый live-запуск: `STRAT_CLIP=5`, `RISK_DAILY_STOP_USD=10`, и сверка журнала с балансом.

## Ограничения, о которых нужно знать

- Модель исполнения не учитывает влияние собственных ордеров на рынок.
- Спот берётся с Coinbase/Binance, рынок разрешается по Chainlink. Поток Chainlink TWAP доступен
  через SDK только с авторизацией и в исследовании не использовался.
- Комиссия `0.07·p·(1−p)` и задержка тейкера 250 мс — параметры биржи на ноябрь 2026; при их
  изменении выводы нужно пересчитать.
